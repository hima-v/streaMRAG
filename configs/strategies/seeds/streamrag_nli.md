HELD-OUT CONDITION (not a root of the evolving archive; needs the NLI harness variant, not implemented yet).
Split each new item into atomic facts (one entity, one attribute, one value). For each fact, the harness provides the NLI relation to related memory lines, labelled reinforce, add, state change or conflict. Reinforce: add the item id to the existing line. Add: add a new line. State change: keep the old line with its time span closed and add a new line for the new state. Conflict: keep both lines and mark them as conflicting. When over budget, first merge reinforcing duplicates, then compress runs of identical states, then delete weakly supported facts; never delete the current state of a tracked thing, the last line before a state change, or either side of an open conflict.
